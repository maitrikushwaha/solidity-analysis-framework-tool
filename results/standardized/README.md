# Standardized predictions (unified, self-describing)

Every tool's per-contract results, reshaped into ONE schema so a reviewer can
read any row without guessing. Generated by `scripts/make_predictions.py`;
the raw native tool outputs are kept untouched under `results/<tool>/`.

## Files
- **`predictions.csv`** — consolidated master table (all tools, datasets,
  contracts, vulnerabilities in one file). Load this for any analysis/plot.
- **`<tool>__<dataset>.csv`** — convenience slices of the master table.
- **`_validation.csv`** — QA audit: each (tool,dataset,vulnerability) cell's
  reconstructed TP/FP/TN/FN vs `../metrics_per_class.csv`. Proof of consistency
  (regenerable; not a result).

## Columns
| column | meaning |
|---|---|
| `tool` | ours / mythril / oyente_plus / slither / osiris / smartcheck / sailfish |
| `dataset` | rsd / sbc / qian / solidifi |
| `contract` | canonical id: qian = `<category>/<file>.sol`; rsd/sbc/solidifi = `<file>.sol` |
| `vulnerability` | reentrancy / overflow / timestamp / tod |
| `label` | safe / vulnerable (= vulnerable iff ground_truth = 1) |
| `ground_truth` | 0/1 |
| `predicted` | 0/1 |
| `outcome` | TP / FP / TN / FN |
| `source` | the authoritative artifact each row was derived from |

## Crash / compile-error handling
Contracts a tool could not analyse (compile error, timeout, crash) are treated
as **N/A and excluded** — never counted as TN or FN — matching the paper's
convention. This is why, e.g., Slither's 2 SBC parser crashes are not its false
negatives, and Mythril's 2 RSD timeouts are not true negatives.
